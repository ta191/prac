こえのアトリエ / VoiceAI Local 0.1.0

Windows PC内で使う、日本語のボイスクローン・音声変換・テキスト読み上げアプリです。
Windows 11 x64・NVIDIA GPU向けの初期版です。GPUの互換性・速度は実機で確認してください。

**現状：アプリと実モデル呼び出しを実装済み。Windows実機・GPUでのモデル生成は未検証です。**
本アプリは動作検証用の初期版です。声の再現性や速度を確認してから、長い文章や録音へ用途を広げてください。

**簡単な起動方法**

GitHubのZIPを展開して `prac-main` フォルダーを `VoiceAI` に名前変更し、Eドライブへ移動して、`E:\VoiceAI\START.bat` をダブルクリックしてください。初回は環境構築・モデル取得を順番に行い、完了するとブラウザを開きます。2回目以降も同じファイルで起動できます。

**個別に実行する場合**

1. 配布された `VoiceAI` フォルダーを外付けSSDへ展開し、`E:\VoiceAI\01_setup.bat` がある状態にします。ZIP内から直接起動しないでください。
2. `01_setup.bat` をダブルクリックします。専用Python・依存ライブラリ・FFmpeg・Seed-VCのコードを無料の公式配布元から取得します。既存のPythonやシステムPATHは変更しません。
3. 完了したら `02_prepare_models.bat` をダブルクリックします。Qwen3-TTSとSeed-VCの重み・関連モデルをダウンロードし、1つずつGPUへ読み込めるか確認します。初回はネット接続と時間が必要です。
4. `03_start.bat` をダブルクリックします。ブラウザで `http://127.0.0.1:7860` が開きます。
5. 「ボイスを登録」から、自分または許可のある人の音声を登録します。音声中の発話を文字起こし欄へ正確に入力すると、TTSの再現性を高めやすくなります。
6. 「音声変換」「テキスト読み上げ」で、同じボイスを選んで生成します。
7. 完成した音声は試聴して、WAVまたはMP3で保存できます。

2回目以降は `START.bat` または `03_start.bat` で起動します。外付けSSDは使用中接続したままにしてください。
終了は起動時の黒いウィンドウで Ctrl+C を押します。ブラウザを閉じるだけではアプリは停止しません。

起動ファイルは、その1回のPowerShellプロセスに限って `ExecutionPolicy Bypass` を指定します。Windows全体の実行ポリシーは変更しません。

**最初の実機テスト**

- 10秒程度の、BGMがない明瞭な日本語の声を登録する。
- TTSで「こんにちは。今日は良い天気ですね。」を生成する。
- 別の10秒程度の録音をアップロードし、同じボイスへ変換する。
- 両方を聞き比べ、声の似方・読み間違い・変換前後の内容と間を確認する。
- WAV・MP3の両方を保存し、Windowsのプレーヤーでも再生する。
- アプリを終了して再起動し、ボイスと履歴が残ることを確認する。
- モデル準備後にネット接続を切って、もう一度生成する。

処理時間は画面に表示します。詳細な推論時間・生成音声の長さ・最大GPUメモリ使用量は `data\jobs\<ID>\metrics.json` に記録します。起動・モデル読込を含む画面の時間とは範囲が異なります。

**初期版の範囲**

| 項目 | 内容 |
|---|---|
| 参照音声 | WAV／MP3、3〜30秒、40 MB以内 |
| 変換元音声 | WAV／MP3、0.5〜60秒、40 MB以内、単一話者を想定 |
| 読み上げ | 日本語、500文字以内。最初は短文で確認 |
| 出力 | WAV・MP3（192 kbps）。実際の音質はモデルの生成結果に依存 |
| 実行 | GPU使用、1処理ずつ。各処理後にワーカープロセスが終了しメモリを解放 |
| ボイス登録 | 元音声と文字起こしを永続保存。モデル用の特徴は生成時に計算 |
| 未搭載 | 追加学習、リアルタイム通話、複数話者分離、BGM分離、自動文字起こし |

「即時クローン」は参照音声から声を再現する方式です。登録時に専用のモデル重みを追加学習するものではありません。
Qwen用の特徴や重みをSeed-VCへ流用せず、同じvoice_idに登録された元音声を両機能が参照します。
声質が両エンジンでどの程度一致するかは、実音声で確認する必要があります。

**PCへの配置**

```text
VoiceAI/
  START.bat              初回準備から起動までまとめて実行
  01_setup.bat           初回の環境構築
  02_prepare_models.bat  モデル取得・GPU読込確認
  03_start.bat           普段の起動
  04_diagnose.bat        PC・PyTorchの診断
  app/ web/ workers/    アプリ本体
  .venv-ui/             画面用Python 3.12（セットアップ時に作成）
  .venv-tts/            Qwen用Python 3.12
  .venv-vc/             Seed-VC用Python 3.10
  python/ tools/       専用Python、uv、FFmpeg
  models/              Qwenなどの重み・準備結果
  vendor/seed-vc/       上流コードとSeed-VCの一部キャッシュ
  cache/ logs/         セットアップキャッシュ・診断ログ
  data/                ボイス、履歴、生成音声
```

モデル、Python、作業用キャッシュはこのフォルダーの下に置くよう設定しています。ブラウザやWindows自身の一時データまで配置先を変更するものではありません。
ボイスの削除は参照音声と登録情報を削除します。生成済み音声は履歴に残ります。バックアップする場合はアプリを終了して `data` フォルダーを保存してください。
モデル準備後にアプリの配置先を移した場合は、`02_prepare_models.bat` を再実行してください。

**エラーが起きたとき**

| 状況 | 対処 |
|---|---|
| 初回準備に失敗 | 表示されたエラーと `logs\setup.log` または `logs\models.log` を確認。依存関係の無差別な更新はしない |
| GPUが使えない | `04_diagnose.bat` を実行し、`logs\diagnose.log` を確認 |
| GPUメモリ不足 | 他のGPU使用アプリを閉じ、短い文章・録音で再実行 |
| モデルが見つからない | ネット接続のある状態で `02_prepare_models.bat` を再実行 |
| 生成に失敗 | 画面の「ログ」を開く。音声内容を送らなくても、まずエラー文から調査できる |
| 画面が開かない | 起動ウィンドウのエラーを確認。正常起動ならEdge/Chromeで `http://127.0.0.1:7860` を開く |
| ポート7860が使用中 | 既に起動したこのアプリがないか確認。先に起動したウィンドウを使用する |
| モデル準備後もボタンが無効 | ブラウザを更新する |

GPUが使えないとき、遅いCPU実行へ無断で切り替えず、原因を表示して停止します。
初回準備以外の推論ではHugging Face／Transformersのオフラインモードを設定します。公開共有リンクや有料APIは使用しません。

**検証状況**

- Linux開発環境で13件の自動テストが成功。入力検証、永続化、共通ボイス参照、キューの逐次処理、実プロセスのキャンセル、エラー後の復旧など。
- 実際のFFmpegでWAV／MP3を生成・デコードする経路を検証。
- Chromiumで登録・編集・削除、両画面のボイス選択、再読込後の保持を確認。1440pxと390pxの表示を確認し、JavaScriptエラーなし。
- Windows x64向けの依存関係を解決し、解決結果を `locks` に固定。
- AIの生成処理を使うテストには代替のテスト用処理を注入しているため、日本語AI音声の生成成功を示すテストではありません。製品の実行経路にはテスト用の音声出力を組み込んでいません。
- Windowsのbat／PowerShellセットアップ、GPU推論、品質・速度、実モデルによるオフライン動作は未検証です。

開発テストを再実行する場合は、UI依存環境へ `httpx==0.28.1` を追加し、FFmpegを利用できる状態で `python -m unittest discover -s tests -v` を実行してください。
